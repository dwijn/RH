title: Hybrid PRD: the PRD sub-iterations keep the gas-frame contributions of the wavelengths they do not re-solve

With `PRD_ANGLE_DEP = PRD_ANGLE_APPROX` the gas-frame mean intensity `Jgas` of a wavelength is the sum of the Doppler-shifted, interpolated intensities of its neighbours (`addJgasRay`, weights of `prdh.c`), and `PRDScatter` reads it at the wavelengths of a PRD line. `solveSpectrum` zeroed all of `Jgas` before every sweep, also before the sweeps of the PRD sub-iterations (`prdSubIterations`, SOLVER = ANDERSON, FIXED_POINT, NEWTON_KRYLOV; `Redistribute`, SOLVER = NG), which re-solve only the wavelengths with a PRD line. After a sub-iteration the rows of the PRD wavelengths therefore held the contributions of the PRD wavelengths only. Where a wavelength without PRD line has an angle-dependent opacity (a moving atmosphere with another line, or a background line, in its window) and lies within a Doppler shift of the edge of a PRD window, its share of the edge row was missing from the second sub-iteration on, until the next full formal solution. Wavelengths without angle-dependent opacity add to their own row only (`addJgasRow`) and are never the problem, so the effect needs a CRD (or background) line next to the PRD window and a velocity.

Fix. `spectrum.Jgas_fixed` takes the contributions of the wavelengths without PRD line to the rows of the wavelengths with a PRD line, the only rows `PRDScatter` reads; everything else goes into `Jgas` as before. It has a row only for the PRD wavelengths that a wavelength without PRD line can reach, and exists only for hybrid PRD in a moving atmosphere. `spectrum.PRDrow` is the one map: -1 for a wavelength without PRD line, the row of `Jgas_fixed` for a PRD wavelength that can be reached, -2 for one that cannot. `initJgasRows` (`readj.c`, called from `initSolution` with the result of `containsPRDline`, the criterion that selects the wavelengths of a PRD sweep) sets it. The reach is exact enough and cheap: a wavelength gives to the grid points from `r[0]` to `r[2]` of its `prdhBracket`, both ends do not decrease with the shift, and the shift of any ray at any location lies between 1 - vmax/c and 1 + vmax/c (vmax the largest |v_los|, fixed in a run), so the range from the bracket at the smallest shift to the one at the largest holds every point it can give to: two brackets per wavelength at the start, independent of the iteration. A contribution of a wavelength without PRD line to a PRD wavelength with PRDrow = -2 cannot happen; `jgasRow` stops the run with ERROR_LEVEL_2 naming both wavelengths if it ever does. `beginJgas(redistribute)` zeroes `Jgas` and, before a sweep of all wavelengths, `Jgas_fixed`; before a PRD sweep it starts the rows of the PRD wavelengths that have one from `Jgas_fixed`. `endJgas` adds `Jgas_fixed` to those rows after a sweep of all wavelengths. After every sweep of all wavelengths `Jgas` is what it was (summed in a different order); after a PRD sweep the PRD rows are those of a sweep of all wavelengths with the current `rho` (the other rows are incomplete, as before: nothing reads them, and the next full sweep rebuilds them). Memory: `Nrows * Nspace` doubles. Rows stored, of the PRD wavelengths: 8 of 708 (1.1 %, 1621 wavelengths) for H_6, Ca II and Mg II active with the hybrid approximation on FALC_v10 (3 rays); 2 of 95 PRD wavelengths (of 287) in the K-CRD test case at 1, 3 and 10 times the velocity of FALC_v10. At rest nothing is stored (FALC_82: 708 PRD wavelengths of 1647, no row). `addJgas` is now local to `readj.c`. No change for the other PRD modes and for static atmospheres. Both paths use the same `solveSpectrum`, so SOLVER = NG and the G solvers are covered by one change.

What was measured. Diagnostic build (not committed): after each PRD sub-iteration, the contributions of the wavelengths without PRD line to the rows of the PRD wavelengths. In the Ca II H and K cases of the tests (both lines PRD; `FALC_v10.atmos` and the same scaled to 20 to 100 km/s) it is exactly zero: the PRD windows (+-1500 Doppler widths) cover the other lines and the neighbouring wavelengths are further away than the shift, also with extra wavelengths 0.2 to 0.4 nm from the window edge (these have no angle-dependent opacity). With the H line CRD and the K line PRD (an atom file for this test only) the edge row next to the CRD window lacks a share of 3.9e-2 of its Jgas (one row of 95 PRD rows, FALC_v10, 3 rays) in the old code. The result for the CRD-next-to-PRD case is not small in rho: at the end of a run to ITER_LIMIT = 1e-4 with the default solver (ANDERSON) at 3 times the velocity of FALC_v10, the first PRD sub-iteration of the old code still changes rho by 3.6e-2 (it uses the Jgas of the sweep, the second sub-iteration the incomplete one and undoes it), so the converged state of the old code is not a fixed point of the PRD iteration; the new code has 1e-5 (ANDERSON) and 2e-7 (FIXED_POINT). J changes much less, since the PRD edge rows are a small part of the line: largest relative difference of J at convergence, ANDERSON: 9.3e-5 (FALC_v10), 3.9e-6 (x3), 2.6e-6 (x4); FIXED_POINT: 9.8e-8 (x3); NG: 8.9e-7 (x1). The iteration counts of ANDERSON are the same (34, 33, 41 at x1, x3, x4) and FIXED_POINT takes 84 iterations in both.

SOLVER = NG, K-CRD case at 3 times the velocity: the old code converges in 84 iterations and the new does not (100 iterations, a cycle of period 4 in the populations, period 2 in the number of PRD iterations). Mechanism: not Ng (the cycle stays with PRD_NG_ORDER = 0 and NG_ORDER at its default of 0, and does not depend on the lag of the fixed part: a variant that re-solves all wavelengths in every PRD iteration, so that the fixed part is the reference, shows the same cycle). With SOLVER = NG the PRD loop stops as soon as the change of rho is below PRD_ITER_LIMIT (1e-2); in the new code rho is consistent, so every other main iteration stops after one PRD iteration (change 7e-4) and the next one starts with a change of 1.1e-2 and runs all three (changes 1.1e-2, 2.9e-2, 3.4e-3). The coupled iteration of populations and rho is near an eigenvalue of -1 here and the early exit of the PRD loop is a threshold that locks it into a limit cycle. In the old code rho is never consistent (every main iteration has a change of 3.8e-2 in the first PRD iteration), the loop never exits early, and nothing flips. This is NG's early exit of the PRD loop (pre-existing, N-4 (a)), not a defect of the fix: the contrived K-CRD case at 3 times the velocity no longer converges with SOLVER = NG and the default PRD_ITER_LIMIT, and the default solver is unaffected. The cycle goes away with PRD_ITER_LIMIT = 1e-4 and PRD_N_MAX_ITER = 30 (84 iterations, both codes, with or without PRD Ng), is not specific to the fix (the old code with PRD_N_MAX_ITER = 1 does not converge either), and does not occur with ANDERSON and FIXED_POINT, the default and the G solvers. NG_ORDER = 4 converges in 18 iterations with both.

Tests. `test_jgas_split` (new unit test): 240 grid points, PRD wavelengths among them (a block of 70 whose inner part no other wavelength reaches), random velocities, `addJgasRay` with the interpolation table, `initJgasRows` and the compact `Jgas_fixed`. After a PRD sweep with new intensities at the PRD wavelengths `Jgas` at those equals a sweep of all wavelengths with the same intensities to 1e-13, for three generations in a row; zeroing `Jgas` as before differs by more than 1e-3 (the test sees the old behaviour); without `Jgas_fixed` everything goes into `Jgas`.

`ctest`: 38 of 38 with the CI flags (`-DRH_WARNINGS=ON -DRH_WERROR=ON`) and with icx. `clang-format --dry-run --Werror` clean on the changed files. `run_tests.sh` against a build of origin/modernize (2d96f27), tolerance mode: passed 38, failed 0; all 12 cases byte-identical at N = 1. The K-CRD case with the compact map gives J, rho and populations bit-identical to the version with a row for every PRD wavelength.
