title: waveinfo checks its read: a wavelength file it cannot read is reported as an error, with status 1; a file read ends with status 0

`tools/waveinfo` read the number of wavelengths and the wavelengths without checking either read, and printed what it had. An empty file gave "Found 0 wavelengths, ranging from 0.000 to 0.000 [nm]" from an uninitialized count, reading outside the array; a file with a count of 5 and two values gave "Found 5 wavelengths" and values never read. A count of 0 also read outside the array. Its exit statuses were the wrong way round: 0 for a file that did not open, 1 for a file read. Now a file that does not open, ends before the count or before the wavelengths it announces, or gives a negative count is reported on stderr ("Error reading file: ..." with what is missing) and waveinfo ends with status 1; a count of 0 gives "Found no wavelengths"; a file read ends with status 0. The usage message still ends with status 255, as before. The same in upstream RH (`tools/waveinfo.c:102-105`). New e2e test `waveinfo` (when the tools are built): a file of 7 wavelengths, a count of 0, an empty file, a short file, a negative count and a missing file. Results unchanged (`run_tests.py --exact`; no test used `waveinfo`).
