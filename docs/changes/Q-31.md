title: The end-to-end test scripts share one helper package, tests/rhtest

The eight scripts of `tests/e2e/` each carried their own copy of the same plumbing: argument parsing (`--src`, `--work`, the program paths), the work directory (`mkdtemp`, removed on a pass, kept and named on a failure through an identical `_name_work` excepthook, eight copies), the Atoms/Atmos/Molecules links, `setkw` (seven copies in two variants: one where the value `None` comments the key out, one without), the preparation of a run directory from `<geom>/run/keyword.input` (five variants of `run()`, two of `execute()`, two of `prepare()`), the `atoms.input` text, the struct readers of `pops.*.out`, `J.dat`, `spectrum.out` and the solveray output, `maxrel`/`maxdiff`/byte comparison, and the pass/fail bookkeeping (three variants of `check()`). Q-31 moves that into a standard-library-only package `tests/rhtest/` (no numpy: the CI build jobs have none) and ports the scripts onto it. Results are unchanged and so is what the tests check: same cases, keyword values, tolerances and exit statuses (0 pass, 1 fail). The scripts find the package with a two-line `sys.path` insertion of `tests/`, so they still run by hand; `rh_add_e2e` in `CMakeLists.txt` is untouched.

Where things went: `cli.parse` (the common arguments); `workdir.WorkDir` (the lifecycle: `--work` is kept, a temporary directory under `$TMPDIR` is removed by `finish(True)` and otherwise kept and named at exit, also after `sys.exit` and uncaught exceptions; the links); `keywords.setkw`/`apply`/`edit_file`/`atoms_input` (one `setkw`, the variant where `None` comments the key out; the other variant, in `prd_hybrid`, `solver_default` and `stokes_1d`, never got a `None`, and with a value the two are the same code); `run.prepare`/`setup_dir`/`copy_dir`/`execute` and `Result.require` (run directories from a geometry's template, running with a timeout and `out.log`, the exit-status test, with the end of `out.log` in the message), `run.completed` and the `EXIT_*` constants (the status classes of `run_tests.sh completed()` and `error.h`); `output.read_pops`/`read_doubles`/`read_stokes_spectrum`/`read_solveray`; `check.Checker`, `maxabs`, `maxdiff`, `maxrel`, `same_file`. The shell harnesses `run_tests.sh` and `run_stress.sh` and the numpy scripts `analyze_run.py` and `compare_spectra.py` are not ported; `keywords`, `run` and `output` are written so that they could be.

Measured: every script was run on the base build with the old and the ported version, each with `--work`, and the work trees compared. All 501 `keyword.input`, `atoms.input`, `molecules.input`, `ray.input`, atmosphere, field and atom files written or copied are byte-identical, except that absolute paths differ where a script writes one (`ATMOS_FILE` of `prd_hybrid`'s moving atmosphere, `STOKES_INPUT` of `solveray_cosines`: the two work/source trees), and the 2092 other files (outputs, `J.dat`, `spectrum.out`, `pops.*.out`) identical apart from `time.out` and the modification time of the atmosphere file that RH writes into some outputs. `solver_g`'s 2-thread `gcheck_2d/background.dat` differs between any two runs, old script or new. Small behaviour differences, none in a check: `solveray_cosines` now also leaves an `out.log` in each solveray directory; a program exit that stops a test (bad status, timeout) names the kept directory (before, `sys.exit` skipped the hook); a failing `solver_*` run now shows the end of `out.log`; `stokes_1d` keeps its absence of a timeout (the ctest timeout of 900 s applies). The per-script summary line is unified to `<name>: all N checks passed`. The scripts shrink from 1697 to 1141 lines, the package is 393.
