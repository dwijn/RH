title: The G solvers check every keyword that is set, whatever the atoms; an unset PRD_ITER_LIMIT is 0 under them

First step of `ANDERSON` as the default solver (docs/SOLVER.md, Anderson as the default solver, item 2, decided 2026-11-10): every keyword that is set is checked against the solver that runs, and no check depends on the atoms; a default is never a conflict. Under `FIXED_POINT`, `ANDERSON` and `NEWTON_KRYLOV` an unset `PRD_ITER_LIMIT` is now 0 (`PRD_N_MAX_ITER` sub-iterations per G), where its default 1.0E-2, which belongs to `NG`, used to stop the run; set to anything but 0 it still stops the run. Keywords without an "off" value stop the run when they are set at all: `NG_DELAY` and `NG_PERIOD` under `ANDERSON` and `NEWTON_KRYLOV` (`FIXED_POINT` keeps the Ng keywords for its "Ng on G" control), and `PRD_NG_DELAY`, `PRD_NG_PERIOD` and `COLL_RELAX_FACTOR` under every G solver; they used to be ignored silently. `NG_ORDER` and `COLL_RELAX_NSTEP` stop the run when they are not 0 (negative values included). Runs with `SOLVER = NG` (the default) are unchanged bit for bit. The test tools can remove a keyword from a shipped keyword file: `run_stress.sh --kw '-NG_DELAY'` (and in case keywords), `setkw(text, key, None)` in the e2e tests, whose Anderson and Newton runs now remove `NG_DELAY` and `NG_PERIOD`. New e2e checks: `FIXED_POINT` without `PRD_ITER_LIMIT` in the file repeats the history of `NG` with `PRD_ITER_LIMIT = 0` bit for bit; `NG_DELAY` with `ANDERSON`, `PRD_NG_DELAY` and `COLL_RELAX_FACTOR` with `FIXED_POINT` stop the run at input.
