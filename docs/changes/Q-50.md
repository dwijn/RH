title: The statics left for phase 3: return buffers are the caller's, the warn-once flags are in rh (results and output unchanged)

The library kept a few more things of a run in static variables, which two solvers in one process would share:

- **Return buffers.** `NgStatus` and `linearNote` (the end of a log line about Ng acceleration and about the wavelengths solved linear) and `getAtomID` and `getMoleculeID` (the ID on the first line of a model file) returned a static buffer. The caller now passes the buffer. `getAtomID` and `getMoleculeID` write the ID into an array of the caller and return nothing, the form that Q-51 gives them with a status.
- **Warn-once flags.** The notes that the H₂⁻ and H₂⁺ free-free tables end (written once per run from the background-opacity threads) are atomic flags in `rh->hydrogen`; the note on `PRD_DAMPING` is in a new part `rh->redistribute`. The PRD note was written once per process, now once per run.
- **`setOptions`.** The name of the log file is a local array: nothing uses it after the file is opened. The static for a wavelength table was never set (there is no such option), and the field `rh->commandline.wavetable` it went to was never read; both are gone, and so is `rh->commandline.molecule`, which nothing used.

What stays static: the tables loaded once (phase 4), and the file handles and the thread-local Jgas buffers of `readj.c` (phase 5).

Checks: `run_tests.py --exact` against the base, and all files of the runs of the end-to-end tests compared with the base, byte for byte. Scripts and logs: `claude/RH/evidence/lib-q50-statics`.

Phase 3 of the library track (`docs/LIBRARY.md` §6.3).
