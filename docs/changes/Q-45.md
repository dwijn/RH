title: The globals in one struct, RHState, reached through rh (results unchanged)

The programs defined seven globals that the library used: `topology`, `atmos`, `geometry`, `spectrum`, `stats`, `input` and `commandline`. They are now fields of one struct, `RHState` (`src/include/state.h`), reached through a const pointer: `atmos.T` is now `rh->atmos.T`. Each program defines the one instance with a static initializer, as it defined the globals: `static RHState rh_state = RH_STATE_INIT(ONE_D_PLANE, &geometry_data); RHState *const rh = &rh_state;`. The type of the geometry differs per geometry, so `RHState` holds a pointer to it (`struct Geometry *`): `geometry.Ndep` is now `rh->geometry->Ndep`. The tools in `tools/`, which defined only `commandline` (one also `input`), define a zero-initialized instance.

Why `rh->` and not `rh.`: in phase 3 the struct becomes a parameter, `RHState *rh`, which takes over the name, so the code that uses it does not change again. Because `rh` is a const pointer, the compiler loads it once per function and keeps it across calls (probe in `claude/RH/evidence/lib-phase2-survey`). `messageStr` stays a global until errors return (phase 3, T-1).

The rewrite was made by a script, `q45_rewrite.py`, followed by clang-format: the second commit is its output, and running both on the first commit reproduces it exactly. Machine code: built at -O0, where gcc translates each expression as written, all 360 object files (library, programs, tools, unit tests) have the same instructions as before, with only the symbol of each access changed (`atmos+X` against `rh_state+offset+X`); a deliberate one-field mistake is found by the same comparison. Timing, on the 3-D timing case of `run_stress` (two runs each, the order swapped): no difference above the run-to-run spread of the base, about 5% in CPU time; at -O3 the functions that do the work per point and ray in the 3-D solver have the same instructions as before. Scripts and logs: `claude/RH/evidence/lib-q45-rewrite`.

Also: `rh.h` has an include guard (state.h includes it), the geometry structs carry the tag `struct Geometry`, and metal.c's own `N_MAX_OVERLAP` (10 overlapping metal lines) is renamed `N_MAX_METAL_OVERLAP`, since state.h brings in spectrum.h's (500 transitions).

Part of Q-4; phase 2 of the library track (`docs/LIBRARY.md` §6.3). Results unchanged: `run_tests.py --exact` against the base, all geometries.
