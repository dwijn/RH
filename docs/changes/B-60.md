title: OLD_POPULATIONS reads only the populations, not the LTE populations of the file; a populations file of another atmosphere or model stops the run

B-60. `readPopulations` (`pops_xdr.c`) passed `atom->nstar` to `xdr_populations`, so it read the LTE populations n* from the populations file as well as the populations n (its comment said it passed NULL, as `readMolPops` does). For an ACTIVE atom with `OLD_POPULATIONS` the file is read in `initSolution`, after `Background` → `SetLTEQuantities` has computed n* for the current atmosphere and electron density, and the file's n* stayed for the run unless `SetLTEQuantities` ran again (SOLVE_NE = ITERATION, hydrostatic): the collision rates had the current n*, the bound-free terms (radiative rates, opacity and emissivity of the continua) the file's, and the populations file written at the end carried the file's n* (so the departure coefficients n/n* were wrong). For a PASSIVE atom the file is read in `readAtom` and n* is recomputed later, so nothing changed there. Now `readPopulations` reads n only; n* are always those of the current run. `writePopulations` still writes both.

Measured (FAL-C, `rhf1d/run`, Ca II active, 1 thread, ITER_LIMIT 1e-4, modernize c204d76; evidence `/hao/solar1/dwijn/claude/RH/evidence/pops-nstar/`, README): run A (SOLVE_NE = NONE) writes pops.CA.out; B restarts from it with SOLVE_NE = ONCE (n_e -15 % to +9 % against the atmosphere file), C starts with ZERO_RADIATION and SOLVE_NE = ONCE. Before: B kept A's n* exactly, up to 15 % from C's, and converged to populations up to 15 % from C's, the Ca II H and K cores 0.46 % (mu = 0.953). Now: B has C's n* exactly and its populations agree with C's to 2.7e-4 (the convergence tolerance). With the same settings (A2 from A, SOLVE_NE = NONE) n* are identical before and after, so restarts that change nothing that the LTE populations depend on give the same results as before.

B-61. `xdr_populations` checked a populations file against the current atmosphere with `strstr(fileID, currentID)` and only warned on a mismatch, so populations of another atmosphere with the same number of depths were used, without even the warning when the current ID is part of the file's (`FALC_8` against `FALC_82`); another number of levels or depths gave "Unable to read from input file". Following the policy that malformed input stops the run, the IDs must now be equal (`strcmp`), else the run stops with both IDs; another number of levels or depths stops with both pairs. Atoms and molecules (`readMolPops`) go through the same check. The check is still the ID only: an atmosphere changed in place that keeps its ID is not caught.

Results: unchanged, except for active atoms restarted with `OLD_POPULATIONS` in a run whose LTE populations differ from those of the run that wrote the file (another electron density, abundance or atmosphere with the same ID), which now get the LTE populations they should have had. `run_tests.sh --exact` against a build of c204d76: all 38 checks pass, the 12 comparisons with the baseline byte-identical (no case restarts from a populations file).

Tests: `tests/e2e/pops_file.py` (new, 8 checks, 3 s): A2 has A's n* and populations to the tolerance; B has C's n*, which differ from A's by 15 %, and C's populations to 5e-3; atmosphere IDs `FALC_XX` and `FALC_8` against a file of `FALC_82` stop with the message; Ca II populations read for He stop ("Populations have 6 levels at ..."). On a build of c204d76 six of the eight fail (B keeps A's n* and converges 15 % away; the mismatched IDs run; the wrong model gives "Unable to read").
