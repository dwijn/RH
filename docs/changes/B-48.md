title: rhanalyze reads and writes XDR with its own module, the same on every Python version

`rhanalyze` imported `xdrlib`, deprecated in Python 3.11 and removed in 3.13, and on 3.13 and later switched to `mda_xdrlib`, an outside package that RH declared nowhere (the switch also tested only the minor version). The new module `python/rhanalyze/xdr.py` (about 120 lines, standard library only) implements the part of `xdrlib` that rhanalyze uses, with the same behaviour: `Unpacker` (`unpack_int`, `unpack_uint`, `unpack_float`, `unpack_double`, `unpack_fstring`, `unpack_string`, `unpack_farray`, positions, `done`) and `Packer` (`pack_int`, `pack_uint`, `pack_float`, `pack_double`, `pack_fstring`, `pack_string`, `pack_farray`), big-endian with 4-byte padding, `EOFError` on a short buffer, `Error` and `ConversionError` as in `xdrlib`. The seven reader modules import it instead. A randomized comparison with the standard-library `xdrlib` on Python 3.12 (219,275 operations, including short buffers, negative sizes, out-of-range integers, NaN and infinities) gives identical results, positions, exceptions and packed bytes. `rhanalyze.rhout` on the regression outputs (1-D CRD, field-free, full Stokes, Kurucz, two active atoms, 2-D, spherical) returns bitwise identical data with the old code on Python 3.12 and the new code on 3.12 and 3.14, and the atmosphere, magnetic-field and wavelength-table writers produce identical files. rhanalyze still needs Python 3.10 or later (`match` in `rhtools.py`). Q-13 (#64) was closed when the switch to `mda_xdrlib` arrived; this removes the dependency that switch left.
