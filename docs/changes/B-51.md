title: rhanalyze reads the output of runs with an active molecule (level energies, populations file, rhdir)

`rhanalyze.rhout` could not read the output of a run with an active molecule (`Nv > 0`; passive molecules have `Nv = 0` and were unaffected). `molecule.read` used `rhdir`, which it never received (`NameError`); it skipped the level energies `EvJ` that `xdr_molecules` (`writemolec_xdr.c`) writes after `n` for `Nv > 0 && NJ > 0`, a C array `[Nv][NJ]`, so every later molecule and `Hminus` were read out of place; and `read_populations` expected `EvJ` at the start of `pops_mol.<ID>.out`, which starts with the atmosphere ID, `Nv` and `Nspace` like every file of `xdr_populations` (`pops_xdr.c`), used a nonexistent `self.NV` for spherical geometry and stored the populations in `self.Nv`, overwriting the number of vibrational levels. Now `molecule` stores `rhdir` (the directory of `atmos.out`, as `rhout` passes it), reads `EvJ` as `[Nv, NJ]` (J = 0 is column 0), and `read_populations` follows `xdr_populations` as the atomic reader does, checks `Nv` and `Nspace` against `molecules.out` and the geometry, and stores the true and LTE populations in `nv` and `nvstar` (the C names), shaped like `rhatom`'s `n` and `nstar`, `[spatial..., Nv]`. Verified on `1d/crd` with `CO_NLTE.molecule` ACTIVE, four iterations: the base stops with `NameError`; with the fix everything is read to the end of both files, the other molecules and `Hminus` are identical to a passive run, `EvJ[0, 0] = 0`, `EvJ[1, 0]` and `EvJ[0, 1]` are the CO vibrational quantum (2143 cm⁻¹) and 2B (3.8 cm⁻¹), `nv` and `nvstar` are zero above `Tmax` and sum over `v` to the CO density, and `nv/nvstar` is 1 within 3.5×10⁻² where T < 5500 K and between 0.75 and 1.05 elsewhere below `Tmax`. `rhout` output of runs without active molecules, including `3d` (B-49), is bit-identical. Same code upstream (c95bdf6).
