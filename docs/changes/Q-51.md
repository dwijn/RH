title: Errors that return, part 1: the runtime and numerics return a status; all 389 fatal sites classified (results unchanged)

The second part of Q-51. First, all 389 places where the library and the code of the three programs end the process (`Error` at level 1 or 2, or `exit`) were classified by what can reach them: 59 bad configuration, 217 bad or unreadable data, 14 numerical failures, 5 invalid trial points of the outer solver, 13 failed allocations, 4 behaviour of the programs (usage, `-showkeywords`), and 77 broken invariants that only a bug in RH can reach. The table, the rubric and the call graph it was made from are in the evidence. The later conversions follow it module by module.

Then the runtime and numerics, the leaves of the call graph, were converted (11 of their 12 sites):

- `SolveLinearEq` and `LUdecomp` return `RH_E_NUMERIC` for a singular matrix, the report Q-7 asks for, and free what they allocated; `Accelerate` passes it on and returns whether it accelerated through an out-parameter.
- `E1` and `E2` return their value through an out-parameter and `RH_E_NUMERIC` outside their domain (x <= 0).
- `zeroPointAtUnityTau` returns `RH_E_DATA` for an atmosphere whose reference optical depth is not increasing or does not reach 1; `pchipTableInit` returns `RH_E_DATA` for a table without points, with x <= 0 in log x, or not monotonic, and leaves the table empty.
- `parallelFor` and `parallelForDynamic` return a status: a work function that fails records the error and returns, and no further work is handed out.
- Invariants abort with `RH_ASSERT`: the Ng order and period in `NgInit` (`readInput` checks the keywords), `freeMatrix` of a NULL matrix, and `clock()` failing in `getCPU` (it does not on the supported systems).
- Not converted: `checkAlloc`, a failed matrix allocation, still exits; how allocation failures are handled is not settled.

Their callers in modules not yet converted call them through `ExitOnError`, which prints the same message and exits with status 70 as before. Functions that return a status are declared `RH_NODISCARD`, so the compiler rejects a caller that drops it; `E1`, `E2`, `LUdecomp` and `LUbacksubst` are now declared in `rh.h` instead of in each file that calls them, where a changed signature would have gone unnoticed. New unit tests show that a singular matrix, `E1` or `E2` outside their domain, bad interpolation tables, an atmosphere without tau_ref = 1 and a failing `parallelFor` worker give a status and the process goes on (`test_linalg`, `test_functions`, `test_interp`, the new `test_parallel`).

Results and output unchanged. Phase 3 of the library track (`docs/LIBRARY.md` §6.3).
