title: ctest keeps the temporary directories of the e2e tests in the build tree, not in /tmp

All eight scripts in `tests/e2e/` (`stokes_1d`, `prd_hybrid`, `solver_g`, `solver_anderson`, `convergence_report`, `solver_default`, `solveray_cosines`, `solver_newton`) put their run directories under `tempfile.mkdtemp(prefix="rh_e2e_")` unless given `--work`, and `ctest` did not give it, so the runs went under `$TMPDIR`, normally `/tmp`. On the sundogs `/tmp` is the small root filesystem and run output must not go there; the 3-D case of `prd_hybrid` writes `J.dat`, `Jgas.dat` and spectra, and the e2e set writes 334 MB in all.

The root cause is fixed in one place. A function `rh_add_e2e()` in `CMakeLists.txt` registers every e2e test (label, timeout and the property `ENVIRONMENT TMPDIR=<build>/e2e-tmp`), so a ninth test cannot forget it; the directory is made at configure time. Python's `tempfile` and the child processes honour `TMPDIR`, so the scripts keep their default. (`e2e_stokes_1d` had no timeout of its own, and now has the 900 s of the others.)

Cleanup is now the same in all scripts: the temporary directory is removed when the test passes and kept when it fails, with its path printed (`solver_g.py` never removed it and did not print it; `prd_hybrid.py`, `solveray_cosines.py` and `stokes_1d.py` removed it also after a failure). With `--work DIR` the runs stay in DIR, as before. The `--work` help text says this. No output is left in the build tree after a passing `ctest`, and concurrent `ctest` runs on one build tree use different directories. Test infrastructure only: no code of the programs changes.

An uncaught exception (a program that cannot be started, a missing output file) also names the kept directory, through an `excepthook` in each script.

Measured, with the CI flags build (Release, `-DRH_WARNINGS=ON -DRH_WERROR=ON`) and with icx: `ctest -j4` with `TMPDIR` set to an empty directory of mine passes 37 of 37 (8 e2e, 25 unit, 4 start) in both; that directory stays empty and `<build>/e2e-tmp` is empty after the run. Two `ctest -R e2e_prd_hybrid` runs at the same time on one build tree both pass (36 s and 38 s with CI flags, 35 s and 35 s with icx, on a loaded shared host) and leave `e2e-tmp` empty. A forced failure (`prd_hybrid.py --rhf1d /bin/false`, with `TMPDIR` at `e2e-tmp`) leaves its `rh_e2e_*` directory there with the path printed. `e2e_prd_hybrid` takes 37 s (single run, both builds).
