title: Negative NG_ORDER, NG_DELAY, PRD_NG_ORDER and PRD_NG_DELAY stop the run at input instead of crashing it

readInput accepted negative Ng orders, and the run then crashed: `NG_ORDER = -2` with SIGFPE in the first iteration (`Accelerate` took the iteration count modulo `NG_ORDER + 2`), `PRD_NG_ORDER = -2` with heap corruption (`NgInit` allocated a history with a negative or zero row count); upstream ends in a terminating error with garbage symptoms. readInput now stops with an error when `NG_ORDER`, `NG_DELAY`, `PRD_NG_ORDER` or `PRD_NG_DELAY` is negative, under every solver; negative delays were harmless but meaningless. The e2e test `solver_g` checks that both orders at -2 stop at input. Runs with valid values are unchanged.
