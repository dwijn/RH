title: Error() takes a printf format; the global messageStr is gone (results and output unchanged)

`Error(level, routine, format, ...)` formats its message itself. Before, the caller formatted it with `sprintf` into the global `messageStr` (512 bytes) and passed that. Worker threads wrote the same buffer (T-1): with four threads printing 2000 warnings at once through the old code, about a quarter of the warnings came out with another thread's text, a few percent were garbled, some with NUL bytes in the log (`t1demo` in the evidence; the new unit test `test_error` does the same with no error). `ErrorExit` formatted the message once more into a 512-byte buffer, which a message longer than about 460 characters would overflow (B-14, B-41). Now each call formats into a buffer of its own, allocated when the message is longer, and writes the message with one call, so the lines of threads do not mix.

`Error` is a macro over `ErrorMessage` and `ErrorExit`, which carry the `format(printf)` attribute: the compiler checks every format against its arguments, and still knows that the error levels do not return. A script merged the 502 `sprintf` + `Error` pairs and removed the 121 declarations of `messageStr` (generated commit, reproducible); 18 functions that used it otherwise were converted by hand (labels for `getCPU` and `MaxChange`, messages built in pieces, if/else before a shared `Error`), and 15 calls that passed a string as the format now pass `"%s"`. Found on the way, kept as they were: `readAtom` formats "Unable to open input file" and then prints only the file name; `tools/waveinfo` formats a message for a failed read and never prints it.

Checks: an independent check of the generated commit (comments and white space removed, every pair and declaration accounted for by regular expressions), `run_tests.py --exact` against the base, and all files of the runs of the 16 end-to-end tests compared with the base, byte for byte. Scripts and logs: `claude/RH/evidence/lib-q48-messages`.

Part of Q-7; phase 3 of the library track (`docs/LIBRARY.md` §6.3).
