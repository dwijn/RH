title: CI runs on stacked pull requests

CI's `pull_request` trigger was limited to pull requests into `modernize`, so a pull request stacked on another one (based on that one's branch) got no checks until it was retargeted or CI was started by hand (#342, #344). The trigger now takes any base branch. The regression suite already compares with the pull request's base commit (`github.event.pull_request.base.sha`), so a stacked pull request is compared with the branch it builds on, and only its own change has to match or carry `changes-results`. Pushes still run CI only on `modernize`.

A pull request takes its workflow from the merge of its branch into its base, so the change applies to stacked pull requests whose branches contain it; #344, opened before it, still needs a manual start or a push after its base has it.
