title: e2e_prd_hybrid also checks rhsc3d: Jgas = J in a static atmosphere (B-7 was fixed by B-31)

B-7 (3-D: `Jgas` accumulated with the full ray weight `geometry.wmu[mu]` inside the `to_obs` loop, while J gets `wmu = 0.5 geometry.wmu[mu]`) is real on upstream and was fixed on modernize by eaebfa8 (B-31, "review fixes: 2-D/3-D Jgas weight"), which changed the angle-independent branch of `rhsc2d/formal.c` and `rhsc3d/formal.c` to pass `wmu`. B-7 duplicates that part of B-31. In upstream (and before eaebfa8) Jgas was twice J at the wavelengths without PRD line opacity in 2-D and 3-D, and only `Jgas.dat` was affected. Today rhf1d, rhsc2d and rhsc3d pass the same `0.5 geometry.wmu[mu]` to `addJgasRay` and `addJgasRow` as J uses; the code is unchanged by this note.

Test only; results do not change. `tests/e2e/prd_hybrid.py` had cases for rhf1d and rhsc2d but none for rhsc3d. It takes `--rhsc3d` (passed by the `e2e_prd_hybrid` ctest) and runs Ca II with PRD on FALC_04x04x82 with one ray (`SET_VERTICAL`) and one iteration, hybrid and angle-averaged. The static atmosphere gives Jgas = J after any number of iterations, so one is enough, and one ray exercises both branches: the PRD lines take `addJgasRay`, the other wavelengths `addJgasRow`. Checked: hybrid Jgas equals J (tolerance 1e-12) and hybrid J equals angle-averaged J (1e-9).

Measured: with the current code both differences are exactly 0. With the line of eaebfa8 put back to `geometry.wmu[mu]` in `rhsc3d/formal.c` the Jgas check fails with a maximum relative difference of 5.0e-01 (Jgas = 2 J); the J check still passes. The 3-D part adds about 2 s to the test (about 16 s in total on the development host, ctest, serial).
