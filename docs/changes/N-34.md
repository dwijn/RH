title: Collision rates given by formulas are checked for sign and finiteness

Collision records with formulas (`SHULL82`, `BADNELL`, `AR85-CDI`, `AR85-CEA`, `AR85-CHP`, `AR85-CHH`, `BURGESS`) were evaluated without a check, unlike the tabulated records, which N-32 interpolates in log-log so that they stay positive and which stop the run at read time when a value is not finite. Measured on the code before this change (`test_collision_formulas`, synthetic records): `SHULL82` with B = -3 gives a negative rate above T1 / ln 3 (-6.8e-8 s^-1 at 1.8e5 K), and so do `BADNELL` with a negative coefficient, `AR85-CDI` with a negative sum (set to zero without a message) and `AR85-CHH` with 1 + c exp(d T/1e4) < 0. The fits are used at any temperature, except `AR85-CHP` and `AR85-CHH`, which are zero outside [T1, T2], silently.

Policy, the same as N-32 where there is a counterpart, in `collision.c` (`CollisionRate`). What the coefficients alone decide stops the run when the record is read (ERROR_LEVEL_2, naming atom, keyword and levels), only where the formula would give an invalid value: a coefficient that is not finite in any formula record; a negative A in `SHULL82`; a negative T0 in `SHULL82` when adi is not zero, a negative T1 when adi and B are not zero; a negative energy E_i in `BADNELL` for a coefficient that is not zero; a shell energy <= 0 in `AR85-CDI` for a row that is not all zeros (such a padding row is skipped); no coefficients in `BADNELL` or no shells in `AR85-CDI` (checked before the arrays are allocated; before, `BADNELL` wrote its first row of coefficients into a zero-size array); a `SUMMERS` scale outside 0 to 1, the documented range, in which the density factor sumscl summers + 1 - sumscl stays between 0 and 1. The same helper checks the finiteness of the tables (N-32) and of the formula coefficients; the table message is unchanged. Not stopped, as before: `SHULL82` with T_col = 0 (no collisional term, which divided by zero), a negative arad or adi, B < -1, `AR85-CHH` with c < -exp(-d T/1e4) and T1 > T2 in `AR85-CHP`/`AR85-CHH`, because their sign or effect depends on T or on the other terms.

What depends on T is checked on the contribution to the collision matrix C (s^-1; one unit for all records, after the conversion to m^3 and the multiplication by n_e and the Summers factor): a value that is not finite stops the run; a negative one is set to zero (as `AR85-CDI` did, silently) with a warning, once per record, atom and run, giving the number of locations and the smallest value in s^-1 with its temperature. The once-per-run state is in the atom (`Atom.rateReports`, a small set of record keys, created at the first message, freed with the atom or by `freeRateReports`); `CollisionRate` reads the records again whenever the electron density changes and does not warn again, and nothing limits the number of records. `AR85-CHP` and `AR85-CHH` warn once about the locations outside [T1, T2], where the rate is zero as before.

Numerical check of `Atoms/C_I+II_9.atom`, the only shipped atom with formula records (`SHULL82`, `BADNELL`, `AR85-CDI`, `AR85-CEA`, `SUMMERS`): 61 temperatures from 1e3 to 1e6 K (log spaced, ne = 1e18 m^-3), every contribution finite and non-negative, no warning: nothing there is negative or clipped. None of the shipped atoms uses `AR85-CHP`, `AR85-CHH` or `BURGESS`. Seen in passing, not changed (data, to be checked against the sources): all four `AR85-CEA` records of that file give zero rate at all T, because `ar85cea` has formulas only for the Li, Na and Mg to S isoelectronic sequences and C I and C II are the C and B sequences; and the splits of the file between the two C II ²P° levels (g = 2 and 4) are 0.6 : 0.4 for `AR85-CDI`/`AR85-CEA` 0-3, 0-4 and for `SHULL82` and `BADNELL` 3-8, 4-8 (the ratio of the coefficients is 1.5 in each), the reverse of the statistical weights 1 : 2, while `SHULL82` and `BADNELL` 0-3 and 0-4 are the same, unsplit, coefficients.

Tests. `test_collision_formulas` (new, synthetic atom files through `CollisionRate`, read with `fmemopen`, the log captured with `open_memstream`): the formula records of `C_I+II_9` over 1e3 to 1e6 K are finite, non-negative and silent; `SHULL82` with B = -3 matches the formula with the negative part set to zero (relative 1e-9), gives one warning (with the unit), none when called again and one again after `freeRateReports`; `BADNELL`, `AR85-CDI` and `AR85-CHH` negative cases give zero and one warning each; `AR85-CHH` and `AR85-CHP` match their formulas inside the range, are zero outside it and report the range, also for T1 > T2; the read-time errors (child process, exit status 70) and the valid records that must not stop. Run against the code before this change the test fails (negative rates, no messages).

Results do not change: none of the cases of `run_tests.sh` has a formula record (`--exact` against `origin/modernize` 2d96f27: byte-identical), and the rates of the shipped atom `C_I+II_9` are unchanged. The index of the proton density of `AR85-CHP` is a separate change (N-34, `docs/changes/N-34-chp.md`). Same code upstream.
