title: The test drivers: 3-D stress atmospheres named by size, timing cases that run alone, the logs of the compared runs, the whole stress help

Four defects of `run_tests.sh` and `run_stress.sh` that the port to Python (Q-31) kept on purpose, fixed in `run_tests.py` and `run_stress.py`.

1. **`run_stress`: `3d_perf_mgi66` ran on the 24x24 atmosphere of `3d_perf_many`.** A generated 3-D atmosphere was named after the set of the case (`pert_3d_conv.atmos`, `pert_3d_perf.atmos`; a bash `local s=... f=...${s/:/x}...` expanded the `s` of the case loop), so the cases of one set shared the file that was generated first. Now `pert_3d_<NX>x<NY>.atmos` (`pert_2d_<NX>.atmos` was already named by size). Shown with stub programs on all cases: `3d_perf_many` uses `pert_3d_24x24.atmos` (4534968 bytes), `3d_perf_mgi66` `pert_3d_16x16.atmos` (2015928), `3d_pert_h6_ca` `pert_3d_8x8.atmos` (504504); before, `3d_perf_mgi66` and `3d_perf_many` both had the 4534968-byte `pert_3d_perf.atmos`. **Timing and memory numbers of `3d_perf_mgi66` measured before this change were for the 24x24 atmosphere**, not the 16x16 one the case table names. No such number is quoted in docs/ (MODERNIZATION.md, SOLVER.md, the change notes: checked with grep on 2026-11-17); results kept elsewhere, e.g. old `run_stress` result files, carry the error. A work directory kept from before still holds the old `pert_3d_conv/perf.atmos`; they are not used any more.
2. **`run_stress --set all`: timing cases did not run alone.** A perf case started while up to `--jobs` conv jobs still ran, so their wall times and memory were measured next to other work (the help says they run one at a time). Now all running conv jobs finish first, and no conv job starts while a perf case runs. Shown with a stub that prints its start and end: `1d_falc_h20`, `1d_falc_mgi66` (two trees) and `2d_perf_many` (two trees), `--jobs 4`: before, `2d_perf_many` on tree a started within 0.1 ms of the four conv runs; now (stub sleeping 5 s, times from the start of the script) the four conv runs end at +5.6 to +5.8 s, the first perf run starts at +6.4 s and the second at +11.8 s, after the first ended at +11.4 s.
3. **`run_tests`: the logs kept with a failure were not those of the runs compared.** The kept log was that of the run directory prepared last: for a comparison of the candidate with the baseline it was the candidate's (the baseline's was not kept), for `N=3 vs N=1` the 3-thread run's, and for `2d/mem` "tiling failed" the previous case's. Now every failure keeps the runs behind it: one run in `WORK/failed/<name>_<time>/`, a comparison in subdirectories named like the run directories (`base_2d_small_n1/`, `cand_2d_small_n1/`; `N=3 vs N=1`: `cand_..._n1/`, `cand_..._n3/`), a failure raised as an error (no peak memory in `time.txt`, an unreadable `spectrum.out`, a run directory that cannot be made) keeps every run its case made, a run without `log.log` is named in the report, and "tiling failed" keeps the output of `make_tiled_2d_atmos.py` (`runs/tile_2d_mem/log.log`) and prints its last lines, as the old script let the traceback through to the terminal. Shown with stub trees, `--only 2d/` and a candidate tree without the 2-D atmosphere: before, the kept `2d_mem_*` directory held the `keyword.input` of `2d/fullstokes` (`STOKES_MODE = FULL_STOKES`); now it holds the traceback of the tiling script; the comparison failures keep both sides.
4. **`run_stress --help` stopped in the middle of a sentence.** The old `sed -n '2,40p'` of the header cut it at "Every run writes its"; the header ends at line 45. `--help` now prints all of it. `run_tests --help` was checked: the header (`sed -n '2,43p'`) ends at line 43, so it is complete.

`ctest`: 45 of 45 with gcc and with icx; `run_tests.py --exact` of the base build (c204d76) against this branch's build: passed 38, failed 0 (nothing here touches RH).
