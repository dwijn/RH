title: Errors that return, part 4: the configuration code returns a status instead of ending the run (results unchanged)

The configuration code of `src/io` (`readinput.c`, `readvalue.c`, `options.c`, `parse.c` and `getline.c`) had 52 places that end the process. 50 of them are gone; the two that print and exit on request (`-help` in `parse`, `-showkeywords` in `readInput`) belong to the programs and stay for that row. Each site was handled by its class in the Q-51 table and the rule of `docs/LIBRARY.md` §3.6. None is an invariant, so all 50 return an error to the caller:

- `RH_E_INPUT` (46): a keyword value outside its set (the 20 keyword setters: `SOLVER`, `ANGLE_SET`, `S_INTERPOLATION` and the others), a keyword line without a value or a required keyword not set (`readValues`), the checks of `readInput` on keywords and their combinations (`NRAYS`, `ANGLE_SET`, the Ng orders, `PRD_DAMPING`, `LAMBDA_REF`, `STOKES_MODE`, `HYDROSTATIC`, the solver conflicts, `ITER_LIMIT` and `ERROR_LIMIT`, the background-scattering keywords), and a command-line option without its value (`parse`). Also `pthread_setconcurrency` failing for `N_THREADS` (low confidence; kept with its class);
- `RH_E_DATA` (4): the keyword file and the log file that cannot be opened, a data file that ends before all its data was read (`getLine`), and a line with too few items (`checkNread`).

`readInput` and the keyword setters are where the configuration enters the library (validate at the API, §3.6). `readInput`, `readValues`, `setOptions`, `parse` and the 20 keyword setters return an `rh_status`; the setters are called through the keyword table (and the option table of `parse`), whose callback type now returns one. The setters that cannot fail (`setcharValue`, `setintValue`, `setdoubleValue`, `setboolValue`) return `RH_OK`. A failure frees and closes what the function holds: `readInput` closes the keyword file when `readValues` fails, and `parse` frees its option arrays.

`getLine` had a flag: at the end of the file it either ended the run (`exit_on_EOF = TRUE`) or returned `EOF`. Every call passed a constant, and the two kinds of call use it differently (the first ignore the length, the second test for `EOF`), so it is split in two:

- `getLine(rh, fp, comment, line)` returns an `rh_status`: `RH_E_DATA`, with the old message, when the file ends before the line (66 calls);
- `getLineOrEOF(fp, comment, line)` returns the length of the line or `EOF`, and cannot fail (12 calls).

`checkNread` returns an `rh_status`.

The callers outside the converted modules call through `ExitOnError`, which prints the same message and exits with status 70 as before: the readers of atoms, molecules and abundances, `backgropac_xdr.c`, `multiatmos.c`, `solveray`, `chartflow` and the tools for `getLine` and `checkNread` (the later rows convert them), and the programs for `setOptions` and `readInput`. The physics, converted in Q-54, passes the status on: `backgroundOpacities` for the opacity fudge file, `readKuruczLines` for a Kurucz line with too few items, after closing its files.

Unit test `test_config`, in the process, so that LeakSanitizer also checks the frees: `getLine` at the end of a file and `getLineOrEOF` around comments and blank lines; `checkNread`; the setters of `SOLVER`, `ANGLE_SET` and `S_INTERPOLATION` with values outside their sets and valid ones; `readValues` with a line without a value, a required keyword missing and a value its setter rejects; `parse` with an option without its value; `readInput` with a keyword file that cannot be opened and one with an invalid value.

Not changed here: B-82 (the angle-set checks of `readInput`) and B-84 (the warning on thread concurrency) keep their behaviour; which keyword files are accepted is unchanged. A message, warning or error before `setOptions` has set the log file still crashes, as before.

Results and output unchanged; the error messages and exit status of keyword files that are rejected are the same. Phase 3 of the library track (`docs/LIBRARY.md` §6.3). Scripts, checks and logs: `claude/RH/evidence/lib-q56-io-config`.
