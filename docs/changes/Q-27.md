title: Faster CI: drift from upstream only when results change, smaller memory case, fewer runs

CI's slowest job, the Linux regression job with sanitizers, took 13–17 min; on a pull request it now does about half the work. The report of the drift from upstream RH runs on a pull request only with the label `changes-results` or when the comparison with the base fails: otherwise the results match the base, and so does their drift (it cost 3–3.5 min per job, and upstream is now checked out and built only when the report runs). Pushes and manual runs still report it. `2d/mem` tiles the 2-D atmosphere to 96 columns instead of 192: 115 MB instead of 215 MB, of which 8 MB do not grow with the grid, so the old per-wavelength caching (Nspect·Nspace·40 bytes, +85 % of the part that grows) fails it just as clearly, in half the time; CI runs it on Linux only (`run_tests.sh --skip 2d/mem` on macOS, whose RSS noise had needed `--memtol 1.15`). The thread counts checked against 1 thread are 3 and 8 by default (uneven split of the work, more threads than cores); 2 never failed in about 400 CI runs. 3-D runs under the sanitizers at the largest thread count only: the code that runs only with one thread is shared by all geometries and checked by the cheaper cases, and 3-D at 1 thread under the sanitizers took 105 s.
