title: The 2-D Eddington approximation retired; ANGLE_SET = SET_EDDINGTON is 1-D only

`ANGLE_SET = SET_EDDINGTON` in `rhsc2d` (made selectable again by B-57) solved each column on its own as a 1-D two-stream problem: one ray at μ = 1/√3 with weight 1, the Feautrier scheme, no horizontal transfer. A column of such a run is a 1-D run of that column (to the bit against the column alone, to the discretization error against `rhf1d` with `SET_EDDINGTON`), so a loop over columns gives the same, with any angle set. It needed a branch of its own in the 2-D `Formal()`, which the shared transfer driver (Q-42) would have had to carry, and a list of refused cases. Decided 2026-11-24 (`docs/LIBRARY.md` §7).

2-D now refuses `SET_EDDINGTON` at input, as 3-D did, with "ANGLE_SET = SET_EDDINGTON is available in 1-D plane geometry only"; so does the 2-D `solveray`. 1-D keeps it: there it is only an angle set, one ray at μ = 1/√3, solved like any other.

Removed: `Feautrier_2D`, the Eddington branch and its guard in the 2-D `Formal()`, `checkEddington()` and its calls in `rhsc2d` and `rhsc2d_gcheck`, the Eddington cases of the 2-D `getAngleQuadr` and `fillMesh`, and the special cases in `solveray` and `chartflow`. The end-to-end test `eddington_2d` is replaced by `eddington` (1-D runs, NRAYS set to 1 with a warning; `rhsc2d`, `rhsc3d` and the 2-D `solveray` refuse). The results of every other run do not change.
