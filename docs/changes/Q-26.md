title: CI after a merge into modernize honours changes-results

A push event carries no pull request, so `CHANGES_RESULTS` was always false in the CI run that follows a merge into `modernize`, and every merge of a pull request labelled `changes-results` failed there (14 of the 16 failed push runs, e.g. after #232, #328, #332). The regression job now takes the label from the pull request the pushed commit merged: the number from "Merge pull request #N" in its message, else the pull request whose merge commit it is (`commits/{sha}/pulls`). A push that merges no pull request (a direct push) still counts as unlabelled. The job gets `pull-requests: read` for the lookup.
