title: rhanalyze reads 3-D output (THREE_D_PLANE misspelled THREEE_D_PLANE)

`rhanalyze.rhatmos` matched the geometry type against `"THREEE_D_PLANE"` (three E's) in `molecule.read`, `molecule.read_populations` and `atmos.read_Hminus`, so `dim` was never set and reading the `molecules.out` of any 3-D run stopped with `UnboundLocalError`, which made `rhanalyze.rhout` unusable for 3-D output. The spelling now agrees with `enum Topology` in `rh.h` and with the rest of the package (a grep of `python/` finds no other misspelled geometry name), and the three `match` statements raise `ValueError("unknown geometry type: ...")` for any other type instead of failing later with `UnboundLocalError`. Verified on `3d/small` and `3d/fieldfree` of `run_tests.sh`: `rhout` fails on the base and reads everything with the fix (13 molecules, Hminus 4×4×82, I 4×4×24×286, every file read to its end); for `1d/crd`, `2d/small` and `sph/small` all attributes (about 1000 arrays and scalars each) are bit-identical between base and fix. Same code upstream (c95bdf6).
