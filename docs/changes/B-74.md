title: readAtom stops on an atom file that does not open with "Unable to open input file" and its path, not the path alone

`readAtom` formatted "Unable to open input file %s" and then passed only the file name to `Error`, so it stopped with "-TERMINATING_ERROR in routine readAtom" and the bare path, without saying what was wrong. The message is now the one the code meant to print, as RH's other input files have it. The same in upstream RH (`readatom.c:87-88`). A run does not get there today: `readAtomicModels` first opens the file in `getAtomID`, which stops with its own message ("Unable to open inputfile ..."), so `readAtom`'s open fails only if the file goes away between the two. The message matters once the file is opened once (phase 5 of the library track). New unit test `test_readatom`: `readAtom` called directly on a missing file stops with status 70 and the message. Results unchanged (`run_tests.py --exact`).
