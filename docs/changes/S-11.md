title: ANDERSON is the default solver in 2-D and 3-D, extrapolating the populations and the PRD ρ

`rhsc2d` and `rhsc3d` now iterate with `SOLVER = ANDERSON` unless the keyword file sets `SOLVER`, as `rhf1d` and `rhsphere` have since S-10. In 2-D and 3-D `ANDERSON_EXTRAPOLATE` defaults to `POPULATIONS_RHO`: Anderson's history covers the populations and the ρ of the PRD lines, and J is carried from G, as RH's Ng does (S-11 step 1). In 1-D and spherical geometry the default stays `ALL`. Decided by the user 2026-11-13 from the 2-D measurements below (docs/SOLVER.md, S-11, item 6). Without PRD lines the default `POPULATIONS_RHO` runs as `POPULATIONS` without a warning; the warning stays for a keyword file that asks for `POPULATIONS_RHO`. The shipped `rhsc2d` and `rhsc3d` keyword files no longer set the Ng keywords and `PRD_ITER_LIMIT`, which `ANDERSON` refuses; they are kept as comments. Tools that mean Ng pin `SOLVER = NG` (`run_tests.sh` 2d/mem). Keyword files that set Ng keywords without `SOLVER` stop at input with the S-10 message, as in 1-D.

Measurements on modernize 480dd90 (Mg II before B-44; the solvers of a case ran on one host model, Xeon E5-2697 v2). Iterations until the largest relative population change first drops below 10⁻³ and 10⁻⁴, iterations to `ITER_LIMIT` 10⁻⁶, work in formal solutions, wall time and peak RSS:

`2d_perf_many` (128 columns, 15 iterations, quiet host), peak RSS and wall time: `NG` 10.5 GB, 2498 s; `ALL` 39.6 GB, 2502 s; `POPULATIONS` 12.7 GB, 2555 s; `POPULATIONS_RHO` 17.3 GB, 2297 s. The largest change after 15 iterations is 0.28, 0.27, 0.24 and 0.19.

Shipped `rhsc2d` example (Ca II, two PRD lines), iterations at `ITER_LIMIT` 10⁻² and 10⁻⁵, and peak RSS: `NG` 13 and 26, 16 MB; `ALL` 10 and 21, 54 MB; `POPULATIONS` 10 and 27, 19 MB; `POPULATIONS_RHO` 11 and 23, 33 MB.

`POPULATIONS_RHO` needs the iterations of `ALL` on both 2-D cases, with half its memory on `2d_pert_h6_ca_mg` and 44 % on `2d_perf_many`. `POPULATIONS` saves memory but loses most of Anderson's gain: J is carried, and without ρ in the history the PRD lines lag. Against the old default, `POPULATIONS_RHO` takes 1.65× the memory on `2d_perf_many`; a run that does not fit can set `ANDERSON_EXTRAPOLATE = POPULATIONS` (1.2×) or `SOLVER = NG`.

Results change. `run_tests.sh` in tolerance mode against 12118ad: 33 of 34 cases pass; 2d/small differs by up to 2.0e-2 in I (at 854.2 nm). Its `ITER_LIMIT` is 10⁻², so each solver stops about 10⁻² from the converged solution, at a different point. 3d/small is unchanged: it stops after 2 iterations, before Anderson's first extrapolated point is evaluated.
