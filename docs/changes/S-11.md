title: ANDERSON_EXTRAPOLATE = ALL | POPULATIONS | POPULATIONS_RHO: Anderson's history over part of the state, J carried from G (S-11 step 1, default ALL)

First step of S-11 (docs/SOLVER.md, S-11): the new keyword `ANDERSON_EXTRAPOLATE` chooses which blocks of the state Anderson extrapolates. `ALL` (the default) extrapolates every block, as before. `POPULATIONS` extrapolates the populations of the active atoms and molecules, and ne when it is in the state. `POPULATIONS_RHO` also extrapolates the ρ of the PRD lines. The other blocks (J, J20, and ρ under `POPULATIONS`) are carried: every point takes them from G at the last accepted point, as RH's Ng does with J. The history, the variables, the weights and the least squares cover only the extrapolated blocks. x, G(x) and G of the last accepted point stay full, so the memory is 3·N + (3m + 7)·N_x doubles plus (m + 4)·N_x bytes (N_x doubles more with `RELATIVE`), printed at the start (history and variables, and the three full states, separately) with the extrapolated and the carried blocks. On the shipped `rhf1d` example the history and variables take 12.4 MB with `ALL`, 0.15 MB with `POPULATIONS` and 5.0 MB with `POPULATIONS_RHO`; the full states 0.96 MB in each. Before every evaluation the solver checks bit for bit that the carried blocks equal those of G at the last accepted point, and reports the count at the end; the check covers the packing and the copy of the carried blocks, not G. Like every `ANDERSON_*` keyword, it stops the run under another solver. `POPULATIONS_RHO` on atoms without PRD lines runs as `POPULATIONS`, since no keyword check depends on the atoms; the banner shows it. Results do not change: `ALL` is the default, and `run_tests.sh --exact` against modernize 4951ebb is byte-identical. Newton-Krylov, which shares the variable code with every block packed, gives bit-identical populations, J and spectra in its e2e runs. New checks in `e2e_solver_anderson`: with depth 0, `POPULATIONS` and `POPULATIONS_RHO` repeat `FIXED_POINT` bit for bit; a `POPULATIONS_RHO` run with `RELATIVE` and `PER_BLOCK` (three solves) is bit-reproducible; the banner names the extrapolated blocks (Ca II populations, 492 unknowns in 1 block; with ρ 16 072 in 3); with forced rejections (`ANDERSON_SAFEGUARD = 0.5`) the carried blocks agree in every evaluation after the first; `ANDERSON_EXTRAPOLATE` under `FIXED_POINT` and an invalid value stop the run at input.
