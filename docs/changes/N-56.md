title: PRD redistribution weights: the stored float rows are renormalized in double

The PRD redistribution weights are stored in single precision (`prdw_t`, P-8/P-14; upstream kept double). They are normalized in double (W/gnorm, W/norm) before the cast to float, so a stored row sums to 1 only to the rounding of the cast. The dot product with J is accumulated in double.

Measured on the Ca II case (FAL-C, H_6 passive, 1 thread; throwaway diagnostic at the point where a row is written, not committed). Over all 15 580 rows of the angle-averaged/hybrid path, the double row sums to 1 within 1×10⁻¹⁵ and the float row is off by up to 4.4×10⁻⁸. Over all 155 800 rows of the angle-dependent path, the double row is within 4×10⁻¹⁵ and the float row up to 4.4×10⁻⁸. A row is a random rounding of 10²–10³ weights, so the error does not average out within a row. The window of a row (`prdFoldRange`) covers the whole fine grid, so the double row sums to 1 over exactly the weights that multiply J (hybrid PRD uses the same file and path as angle-averaged PRD).

**The fix.** `prdIntegrate` and `prdAngleIntegrate` accumulate the sum of the stored weights of the row next to the dot product, in double, and divide the integral by it. The result is the integral with the row renormalized in double, without a second pass over the row or a change of the file. For the angle-dependent path the sum runs over all absorption directions of the row (`Nrow` weights), the set that was normalized together (`norm`).

**Cost.** One more add per weight, in an independent chain beside the dot product: no measurable change. Angle-dependent PRD, 3 iterations (dominated by the weights' construction), 1 thread: 57.4 s before, 58.0 s after (runs 55.0–59.3 and 56.6–60.2 s). Angle-averaged PRD at `ITER_LIMIT` = 1×10⁻⁹, 1 thread: 12.2 s before (177 iterations), 12.7 s after (182 iterations), i.e. 0.069 and 0.070 s per iteration.

**Effect on results.** The scattering integral changes by up to about 4×10⁻⁸ relative, which shifts ρ at that level. Convergence of the Ca II PRD case with the default `ANDERSON` at `ITER_LIMIT` = 1×10⁻⁹: 177 iterations (max change 8.2×10⁻¹⁰, ρ residual 1.2×10⁻⁹) before, 182 (9.9×10⁻¹⁰, 5.8×10⁻¹⁰) after; the extrapolation takes a slightly different path because its input differs at 10⁻⁸.

No unit or end-to-end test: the weights are built inside static functions of `scatter.c` and exist only in the scratch file, so there is no natural place that sees a row. The renormalization is checked by the run comparisons below.

**run_tests.py** (candidate against the build of 4b665de, 1 thread; default tolerance 1×10⁻⁹ in 1-D and 3-D, 1×10⁻⁷ in 2-D): the PRD cases differ in the emergent intensity by 1.9×10⁻⁸ to 5.6×10⁻⁸ relative. 1-D nostokes 3.4×10⁻⁸ (at 393.3 nm), fieldfree 3.4×10⁻⁸, fullstokes 3.3×10⁻⁸ (Q, U, V up to 2.3×10⁻⁹), twoactive 5.6×10⁻⁸ (121.3 nm), spherical 3.5×10⁻⁸, 3-D small and fieldfree 1.9×10⁻⁸, 2-D cases 2.5×10⁻⁸ (inside their 10⁻⁷ tolerance). The CRD case is bit-identical. The thread-count comparisons (3 and 8 threads against 1) pass at 10⁻¹². This is a change of results below the single-precision rounding of the weights themselves (the label `changes-results` applies); 7 of 38 comparisons exceed the tolerance of 10⁻⁹, all by this amount.
