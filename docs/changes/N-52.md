date: 2026-11-20
title: With S_BEZIER3, the strongly scattering wavelengths are solved and iterated with the linear solver

The background scattering iteration of N-51 diverges with the cubic Bézier solver, the 1-D default. The Bézier operator is not positive (N-52). Where Steffen's limited derivative takes the downwind slope, the local control point is C_k = S_k (1 + 2r/3) − (2r/3) S_k+1, so I_k gets a negative weight on S_k+1. With the velocity field, the Δτ of the up- and downgoing rays differ, and the negative weights no longer cancel in J. At a Kurucz line core in a MURaM column the spectral radius of dJ/du is 1.0035 (1.0096 in a Python port), against 0.99996 with the linear solver. On the same rays without velocities it is 0.99999–1.00005. With Bézier, the iteration leaves about 6800 wavelengths unconverged even in a static atmosphere.

Local fixes of the control point do not get below 1 without losing what Bézier is for:
- **The upwind slope everywhere** is stable, but no more accurate than linear.
- **The upwind slope only where Δτ_uw > 1, 3 or 10** still leaves 2100–3200 wavelengths diverging and fails `test_formal_1d` (interior error 1.5–2×10⁻³ against 8×10⁻⁵).
- **Caps on the negative weight, or thick/thin switches,** reach about 1.0025.
- **BESSER** (cubic Bézier with a limiter on the control point) reaches 1.035.
- **Preconditioning with the linear operator** reaches 1.71.

Keeping the operator positive through a local choice of slopes costs the third order.

**The change.** With `S_BEZIER3`, a wavelength whose largest scattering albedo σ_c/χ below vertical optical depth `BACKGROUND_LINEAR_TAU` exceeds `BACKGROUND_LINEAR_ALBEDO` is solved with the linear solver, for the whole formal solution, and its background scattering is iterated (N-51). The other wavelengths keep the Bézier solver and the lambda iteration, which converges where the albedo below the surface is small.
- **The choice is made afresh in every sweep that updates J**, since the opacity of the active atoms changes. A sweep that does not update J keeps the last choice.
- **The log** prints the number of wavelengths solved linear, and the switches to linear and back, in the per-sweep background scattering line.
- New keywords: `BACKGROUND_LINEAR_ALBEDO` (0.9; ≥ 1 turns it off, and with it the iteration with `S_BEZIER3`) and `BACKGROUND_LINEAR_TAU` (1).

**Results.** MURaM column col_0434_0521 (H, Fe, Mg active, `ITER_LIMIT` = 10⁻³), from `ZERO_RADIATION`, then a restart from its populations:
- **Linear wavelengths.** 22 121 of 60 492 wavelengths go linear in the first sweep. About 2200 switch back to Bézier in each of two early sweeps, as the populations move away from `ZERO_RADIATION`. After that single wavelengths switch, and the last switch comes at iteration 22 of 106 (20 of 32 in the restart). Both runs end with the same 18 812 linear wavelengths (31 %).
- **Convergence.** 106 / 32 iterations, against 100 / 25 with `S_LINEAR` everywhere. Restart vs first, emergent I: median 1.6×10⁻⁷, p99 2.8×10⁻⁵, max 1.9×10⁻³.
- **A sticky choice was worse.** Keeping a wavelength linear for the rest of the run once chosen took 112 / 32 iterations and more formal solutions. The first run kept 4348 more wavelengths linear than the restart (23 160 against 18 815), so the two disagreed by up to 2.4 % (p99 1.8×10⁻³).
- **Bézier and linear differ.** At converged populations this run and the `S_LINEAR` run differ by a median 3.8 % in 255–285 nm, and by up to 40 % at an emission feature at 265.84 nm. About 31 % of the wavelengths now carry the discretization of the linear solver.

Without wavelengths above the threshold nothing changes: `run_tests.py` shows no differences from N-51, because the shipped examples have none. The `e2e_prd_hybrid` case does have some (5 wavelengths), and its Jgas = J checks pass. The unit test checks the threshold, a switch back, a query keeping the last choice, and the counts.
