title: input_atmos.write writes the B file it is given instead of overwriting the one it read

`input_atmos.write(outfile, Bfile)` (`python/rhanalyze/rhatmos.py`) ignored its `Bfile` argument and wrote the magnetic field to `self.Bfile`, the file the atmosphere was read from: the input B file was overwritten, the requested one was never written, and an atmosphere read without a B file wrote none whatever `Bfile` said. `write` now writes (B, γ, χ) to `Bfile` when it is given and writes no B file otherwise, so the input file is touched only if the caller passes its name; if `Bfile` is given but the atmosphere has no field, it raises `ValueError` before writing anything (the atmosphere file included). The docstring states this. A caller that relied on the old in-place rewrite must now pass `Bfile=atm.Bfile`; none in the repository does. Verified for 1-D (`FALC_82`), 2-D (`FALC_03x82`) and 3-D (`FALC_04x04x82`, B files from `tests/make_field.py`, 1-D from a synthetic file) with B doubled: the input B file is unchanged (sha256), the new B file is written and reads back as exactly 2B with identical γ, χ and all other arrays; the written atmosphere and B file are byte-identical (sha256) to what the base code writes when its `self.Bfile` is set to the same path, so only the destination changed. Without a field, `Bfile=None` writes no B file and `Bfile="x"` raises. Same code upstream (c95bdf6).
