title: Errors that return, part 2: the physics returns a status instead of ending the run (results unchanged)

The physics module (`src/physics`) had 85 places that end the process. Now none do. Each site was handled by its class in the Q-51 table and the rule of `docs/LIBRARY.md` §3.6. Four went with dead code. The other 81 became 26 assertions and 61 errors that return; four of them became an assertion and one or two checks where the data enters (below).

- Dead code was deleted, with its 4 sites: `Paschen` and its eigenvalue routine `tqli`, `MolLande_eff`, and a check in `Stark` that could not fail.
- An invariant that only a bug in RH can reach, with confidence high, became `RH_ASSERT`. Examples are the enumerated fit methods of the molecules, tables that `backgroundPrepare` builds first, "not a PRD line", and the dJ of a Zeeman pattern.
- Everything else returns an error to the caller:
  - `RH_E_DATA` (45) for model atoms, collision records, Barklem and Kurucz files, molecule data, the opacity fudge file, and scratch files that cannot be opened, written or read;
  - `RH_E_NUMERIC` (9) for factorials that overflow in the 3j and 6j symbols, a collision rate that is not finite, the free-free Gaunt factor outside its table, chemical equilibrium that does not converge, and rho of PRD outside a trial;
  - `RH_E_NOMEM` (4) for the large arrays of PRD;
  - `RH_E_INPUT` (1) for a model too large for the record numbers of the background file (past `INT_MAX`);
  - `LTEpops` and `LTEpops_elem` with ne <= 0 (2): `RH_E_TRIAL` in a trial evaluation of G, `RH_E_DATA` outside one (ne from the atmosphere), now checked before they allocate.

Four checks moved to where the data enters, as errors that return there (in six places) and an assertion in the function that computes the value, which stays a plain function:

- The range of the factorials is checked in `w3js` and in `w6js`, not in `fact`.
- dJ is checked in `Zeeman`, `MolZeeman` and `RLKZeeman`, not in `ZeemanStrength` and `MolZeemanStr`.
- The neutral ground level of H and He is checked once, in the new `RayleighCheck` that `backgroundPrepare` calls. It used to be checked in `Rayleigh` at every wavelength.

A function that can fail returns an `rh_status` and gives its value through an out-parameter, e.g. `w3js(rh, j1, j2, j3, m1, m2, m3, &w)` and `Gaunt_ff(..., &g)`. Before it returns a failure, it frees and closes what it holds: files, tables and work arrays. Where it holds several, it uses the new `RH_TRY_GOTO(status, label, call)` and a cleanup label (`CollisionRate`, `chemicalEquilibrium`, `backgroundOpacities`, `Profile`, the PRD routines). Two examples:

- `readBarklemTable` and `readKuruczLines` close their files and free the Barklem tables.
- `prdWindowBlock` keeps its buffer when `realloc` fails. It used to lose it.
- A failure in the call of `PRDScatter` or `PRDAngleScatter` that opened the scratch file of the weights closes it, so that the next call computes the weights again instead of reading a file that was never written.
- `Zeeman` and `MolZeeman` free the multiplet they allocated, and `adjustStokesMode` leaves no freed profile behind when `Profile` fails.

The work functions of `parallelFor` record the failure and return. The PRD workers are thin wrappers of status functions, so they free their buffers first.

Large arrays use the new `allocMatrixDouble` and `allocMatrixInt`, which return `RH_E_NOMEM` instead of aborting: `rho_prd`, and the tables of hybrid PRD (`frac`, `id0`, `id1`, the Jgas weights). Other allocations still abort until phase 4.

`getCPU` no longer asserts when `clock()` fails. It warns and switches the timing off. The timing is optional output, and the site had low confidence (§3.6).

The modules that are not yet converted (geometry, io, nlte, transfer) call the physics through `ExitOnError`. It prints the same message and exits with status 70, as before. The unit tests check the status. They now test the error paths in the process (collision records, 3j overflow, the Gaunt table, rho of PRD, ne <= 0 in `LTEpops_elem`) instead of in a child process, so LeakSanitizer also checks that the failures free what they hold.

Not changed here: the three empty checks in `collision.c` and the other bugs that the classification found (B-78 to B-85, logged separately), and B-86, a Barklem table read and never freed for every line with Barklem broadening, found by the review of this change.

Results and output unchanged. Phase 3 of the library track (`docs/LIBRARY.md` §6.3). Scripts, checks and logs: `claude/RH/evidence/lib-q54-physics`.
