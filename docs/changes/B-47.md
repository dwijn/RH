title: run_stress.sh stops with the reason when its selection is empty

`tests/run_stress.sh` used to run nothing and exit 0, with an empty table, when `--set` and `--only` selected no case: `--only` naming a case of another set (the default set is `conv`, so `--only 2d_bf_s1_perf` alone ran nothing), a bifrost case without `--bifrost` or `RH_BIFROST_DIR`, or a misspelled `--set`. It now computes the selection once, before resolving the trees, and stops with status 1 when it is empty, naming each case that `--only` matches but the selection excludes, with every reason (`2d_bf_s1_perf: in set perf, not selected by --set conv; a bifrost case, and no --bifrost DIR or RH_BIFROST_DIR`), or saying that no case name matches. `--set` must be `conv`, `perf` or `all`; an invalid `--only` pattern stops with grep's message, and a pattern starting with `-` is taken as a pattern (`grep -e`). A selection that runs some cases prints the excluded matches as `not run:` lines and proceeds as before.
