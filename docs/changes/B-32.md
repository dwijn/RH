title: Hybrid PRD on large grids no longer overflows its interpolation table

The table of gas-frame interpolation coefficients of hybrid PRD (`PRD_ANGLE_APPROX`, built in `initSolution` unless `PRD_LIMIT_MEM` is set) has one entry per wavelength, ray direction and grid point, 2 x Nrays x Nspect x Nspace. Its size and index were computed in `int` and its cumulative counts stored as `int`, so beyond 2^31 entries the index wrapped and the run crashed. On a 3-D cut of the Bifrost snapshot (42 x 42 x 89, every 12th point) with Ca II, 286 wavelengths and 24 rays, 2.155e9 entries, rhsc3d died with a segmentation fault in `initSolution` after 3 minutes. The index and counts are now `long`, and the allocations are checked. The same run now builds the table and iterates (115 GB, 1 h 38 min for one iteration, most of it spent building the table on one thread). `matrix_int` and `matrix_char` computed their size the same way and now compute it in `size_t` (`matrix_double` already did). Results are unchanged (regression suite byte-identical). Also present upstream.
