title: Chemical equilibrium of the legacy iteration takes the neutral fraction of active atoms from their populations

`chemicalEquilibrium()` (`chemequil.c`) needs the neutral fraction `fn0` of every nucleus: it enters the H- density (`fHmin = ne fn0 PhiHmin`), the molecular Saha equations and so `ntotal`, the molecular densities and ne. For an active atom the map G of the G solvers (`ChemicalEquilibriumOfState`, S-2b) took it from the current populations, normalized by their sum. The legacy path (`ChemicalEquilibrium`: the Background() calls of SOLVER = NG with SOLVE_NE = ITERATION, and the one at setup) took it from the LTE `nstar` unless the run started from OLD_POPULATIONS. The two therefore converged to fixed points of different models, and the legacy result depended on how the run was started.

Now the legacy path takes `fn0` from `atom->n` once the populations of the atom have been initialized, normalized by their sum, as the map G does. "Initialized" is the new flag `Atom.popsInit` (`readatom.c` clears it, `initSolution()` sets it for every active atom after the starting populations are in, whatever the initial solution, OLD_POPULATIONS included). Before that the legacy path uses `nstar`, as every fresh run always did: the setup Background() runs before `initSolution()`, when `n` of an active atom is still zero (H: the populations of the atmosphere file, if it has them, and nothing with HYDROGEN_LTE = TRUE or an atmosphere without nH). A first version of this change used `n` at setup too and died with SIGFPE (fn0 = 0/0) for active atoms other than H and for HYDROGEN_LTE = TRUE; a sum that is zero or not finite now falls back to `nstar` as well, so `fn0` is never NaN. The map G (`ChemicalEquilibriumOfState`) is unchanged. The neutral fraction of an active and of a passive atom is computed by one loop over the levels of stage 0 and one denominator, the sum of the populations used (n of a passive atom is its LTE or file populations): this reproduces the old division by `ntotal` bit for bit in every `run_tests.sh` case.

Cause found by running `1d_falc_solvene` (FAL-C, H_6 + Ca II, PRD, BACKGROUND_DOUBLE, ITER_LIMIT 1e-10, no acceleration: NG_ORDER = 0, PRD_NG_ORDER = 0, PRD_ITER_LIMIT = 0, N_MAX_SCATTER = 50; all 466 iterations, delta 9.8e-11) as A = SOLVER = NG and B = SOLVER = FIXED_POINT (this study, and the experiments C and D, on 936aa39; the numbers under "Measured" are re-measured on c9154c0 with the final change). A against B: populations 4.85e-6, spectrum 1.70e-4 of the peak at 163.2 nm (worst wavelength), lines 4.68e-6; ne up to 1.4e-6, nH 4.6e-6, and H2, CH, NH, OH densities differ by a factor of up to 7e4 at T ~ 9000 K (they are (fn0 n)^2). Experiments with only the `fn0` source switched: C = B with the LTE fraction against A: populations 1.7e-11, spectrum 1.0e-11; D = A with the populations against B: populations 1.7e-10, spectrum 9.8e-9, lines 4.3e-9 (the 1e-10 level of convergence). So `fn0` is the whole difference. The populations are the consistent choice: `Solve_ne` already uses the NLTE H populations, and with LTE fractions a restart (OLD_POPULATIONS) changed the problem.

Measured with this change (candidate build against the c9154c0 build, `run_stress.sh` case `1d_falc_solvene` with the recipe above):
- SOLVER = NG, no acceleration: 466 iterations, delta 9.78e-11 (as before); the result moves by 4.8e-6 (Ca II populations), 4.6e-6 (H), 1.70e-4 of the peak (spectrum), and agrees with SOLVER = FIXED_POINT (NG_ORDER = 0, also 466 iterations) to 2.2e-11 (populations), 2.5e-12 (spectrum), 4.4e-13 (lines); before, the two differed by the amounts above. With NG_ORDER 2 (NG_DELAY 10, NG_PERIOD 3), PRD_NG_ORDER = 0, PRD_ITER_LIMIT = 0 and ITER_LIMIT 1e-6: 58 iterations in both builds (measured with the first version of the change, which differs only at setup), populations 4.8e-6 apart.
- SOLVER = ANDERSON (default) on `1d_falc_solvene` and `1d_shock_h6crd_ne`, ITER_LIMIT 1e-10: iterations 66 and 70 as before; populations differ by 5.8e-11 (H) and 1.8e-11 (Ca II), and 5.8e-12, spectrum by 4.9e-11 and 5.7e-12: noise at the convergence limit (SOLVER.md 3.7). The G solvers already took `fn0` from the populations; with the setup call as before (the first version changed it and gave 2e-10) they now differ only by the last bits of the arithmetic.
- `1d_shock_h6crd_ne` with SOLVER = NG does not work before or after: the iteration oscillates with period 2 (N-6; delta 3.1e2 after 30 iterations without acceleration, 3.5e4 after 700 with Ng). With the change it stops earlier with `badPopulations` (negative LU populations) at iteration 12 (no acceleration) and 200 (with Ng). Use a G solver with SOLVE_NE = ITERATION.

Which other results change: SOLVER = NG with SOLVE_NE = ITERATION and an active atom changes, by the amounts above (4.8e-6 in the populations, 1.7e-4 of the peak in the spectrum on `1d_falc_solvene`): the fixed point is now the one of the G solvers, whatever way the run was started. The setup Background() is as before for a fresh run (`nstar`), so every other case is unchanged: `run_tests.sh --exact` against c9154c0, 38 passed, byte-identical at N = 1 in every case, including `1d/twoactive` and `sph/small`, which the first version of the change moved by 2.0e-4 and 3.0e-4. An OLD_POPULATIONS restart used `n` at setup, where `n` was still zero for every active atom but H (so `fn0` = 0) and the atmosphere-file populations for H; it now gets `nstar` there, like a fresh run: only the setup ne, molecules and background opacity of a restart change, and the iteration that follows is the same as in a fresh run (not measured separately).
