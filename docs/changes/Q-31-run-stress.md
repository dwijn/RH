title: The stress suite is tests/run_stress.py on rhtest; analyze_run.py and compare_spectra.py read through rhtest.output

Stacked on the `run_tests.py` change. `tests/run_stress.sh` (383 lines) is ported to `tests/run_stress.py` (567 lines, standard library only, Python 3.8 or newer; it calls `analyze_run.py`, which needs numpy, as before) and removed; `make_references.sh` calls the Python script. Options, help text (including that it is cut at line 40 of the old header, in the middle of a sentence), the case table and `--list` (identical, 33 lines), the selection and its messages (`--only` is still `grep -E`: the pattern is matched by `grep`, so its dialect and its error text are the old ones), `not run:` lines, the results TSV (`results_<date-time>.tsv`, one line per case and tree) and the printed table are the same, as are the run directories (`runs/<case>__<tree>`, `keyword.input` with `-K` removals, `@NOMOL`, `STOKES_INPUT=@B`, `--threads`, `atoms.input`, `molecules.input`). Cases run in threads: up to `--jobs`, and timing (`perf`) cases in the main thread. Like the old script, a timing case does not wait for conv cases still running (see below).

`analyze_run.py` and `compare_spectra.py`: the binary readers (`pops.*.out`, `spectrum.out` of either layout) are `rhtest.output.read_pops_array(path, lte)` and `read_spectrum_file`; the scripts convert what they return to numpy arrays (big-endian for the pops, as before) and keep their analysis, command lines, output and exit statuses. The in-process spectrum comparison of `rhtest.compare` serves the table of `run_stress.py` and `run_tests.py`. `keywords.unsetkw` is the `unsetkw` of the old script. `paths-ignore` of the workflow names `tests/run_stress.py` in place of `tests/run_stress.sh`; `tests/rhtest` is not ignored (CI uses it). `compare_spectra.py` is no longer used by CI or by the stress script either, and could be ignored too.

Measured, old script (modernize c204d76) against the new one on the same inputs, report and exit status, run directories compared file by file (wall times, memory, `time.txt` and the times in `log.log` normalized; table rows sorted, since parallel jobs finish in any order):
- `--list`, `--help`, no arguments, unknown option, bad `--set`, invalid `--only` pattern, an `--only` that matches nothing, one that names a case of another set, a bifrost case without `--bifrost` (`not run:` and status 1 when nothing else is left; with another case selected, it is listed as not run and the other case runs), a nonexistent `--tree` or `--ref`, a tree without a program: identical, same status (the messages of bash's `cd` become the script's own);
- two cases with two trees (the base build twice) and `--jobs 1` and `--jobs 2`: table and TSV identical (iterations, deltas, trends, FS counts, F_SE, "pops {...}; spec : I=0.0e+00"), 146 run-directory files equal, the `log.log` and `time.out` of the runs differ only in times;
- `--kw '-PRD_N_MAX_ITER;N_MAX_ITER=8;ITER_LIMIT=1e-2'` with a removal, two trees: identical; `--ref` with a reference directory made from a finished run and a run with another `ITER_LIMIT` (`vs ref: pops@1e-6 3.6e-02, spec 3.1e-02 (line 7.3e-03)`): identical;
- all 25 non-bifrost cases with stub programs (`--set all`, `--jobs 8`, also with `--threads 3 --kw '-ITER_LIMIT;PRD_N_MAX_ITER=2;-N_MAX_ITER;@NOMOL=MgH'`): 392 files (every `keyword.input`, `atoms.input`, `molecules.input` and generated atmosphere) byte-identical to the old script's; the bifrost cases with a `--bifrost` directory that does not exist (generator argument construction, `$RH_BIFROST_DIR` too): identical. No Bifrost data were used; the paths with data are untested;
- `analyze_run.py` (summary, pops, compare, compare against a reference; 88 invocations on 12 run directories) and `compare_spectra.py` (721 invocations: 103 pairs of spectrum files, unpolarized and polarized, equal, different, truncated, missing, with `--tol`, `--exact`, `--stokes`, `--no-stokes`): stdout, stderr and status identical before and after, and identical to the in-process `rhtest.compare` result. A corrupt pops file gives the same `ValueError` message and status (the traceback differs in line numbers).
- `ctest`: 44 of 44 with gcc and with icx; `run_tests.py --exact` of the base build against this branch's build: passed 38, failed 0, skipped 0.

Differences: an option without a value was an endless loop (as for `run_tests.sh`) and is now an error; `--jobs` must be a positive integer; `/usr/bin/time` is still required (`need GNU /usr/bin/time`). Behaviour of the old script that is kept, found while porting (not fixed here):
- the name of a generated 3-D atmosphere has the set of the case where the size should be (`local s=... f=...${s/:/x}...` expands the `s` of the case loop): `pert_3d_conv.atmos`, `pert_3d_perf.atmos`. `3d_perf_many` (24x24) and `3d_perf_mgi66` (16x16) share a file, so `3d_perf_mgi66` runs on the 24x24 columns, whichever is generated first, also from an old work directory;
- timing cases do not run alone: with `--set all` the perf case starts while up to `--jobs` conv jobs still run (stub programs that print their start and end: `2d_perf_many` started within 1 ms of four conv runs, in the old script and in the new one);
- the `--help` text stops at line 40 of the old header, in the middle of the sentence about the results file.
