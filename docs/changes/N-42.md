title: Hybrid PRD: prdhBracket tells the ends of the grid by index, so two nearly equal wavelengths no longer give one of them the whole grid

With hybrid PRD (`PRD_ANGLE_APPROX`), each wavelength adds its gas-frame intensity to Jgas at the grid points between its shifted neighbours. `prdhBracket` recognized the ends of the grid by comparing the shifted wavelengths: `prv == gas` meant "first point" and `gas == nxt` "last point", and the points beyond an end are taken with weight 1. Two grid wavelengths within about 1 ulp of each other can shift to the same double, though. `SortLambda` removes exact duplicates only, so such a pair can occur. The upper of the two then took every grid point below it with weight 1, and the lower every point above it. That is a large error in Jgas, and with N-27 (#390) such a contribution falls outside the stored reach and stops the run.

**The change.**
- `PRDhBracket` gains `lo_end` and `hi_end`, set from the index (`nspect == 0`, `nspect == Nspect − 1`).
- `prdhBracket` and `prdhWeight` use them instead of the comparisons.
- A collapsed interval is empty: no grid point lies strictly between two equal wavelengths. So its weight, which would divide by zero, is never evaluated.

No shipped grid is known to have such a pair, and the results do not change (see the checks).

**Test.** `test_prdh`:
- The reference scan of `check_brackets` uses the index ends.
- New `check_collapse` moves grid point 151 of a random grid to 1 ulp above point 150, finds a shift that maps both to the same wavelength, and checks two things: the weights are still a partition of unity, and the collapsed interval is empty from both sides.
- Before the change it fails. Point 150 took the grid points [102, 300) above it, point 151 took [0, 102) below it, and the total weight was off by 1.

Checks:
- **`run_tests.py --exact`** against the base (modernize 45c4982) passes 38/38: results are byte-identical.
- **ctest** passes 52/52 with gcc (`-Werror`) and with icx; clang-format is clean.
