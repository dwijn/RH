title: The regression suite is tests/run_tests.py on rhtest; run_tests.sh is gone

`tests/run_tests.sh` (333 lines of bash, with `tests/tree.sh`) is ported to `tests/run_tests.py` (452 lines, standard library only, Python 3.8 or newer; it stops with a message on an older one, such as the 3.6 of `/usr/bin/python3` on the sundogs). Options, defaults, help text, report lines (`[PASS]`/`[FAIL]`/`[SKIP]`, the numbers and their formats, `passed N, failed N, skipped N`, `FAILED:` lines), exit statuses, the work-directory layout (`WORK/runs/<label>_<geom>_<case>_n<N>`, the Atoms/Atmos/Molecules links, `field_*.B` from `make_field.py`, `tiled_2d.atmos`, `WORK/failed/`) are the same. The script is not wrapped: CI and the docs call `python3 tests/run_tests.py` (the regression job has Python 3.12 from `actions/setup-python` on Linux and macOS, also for the sanitizer and upstream-baseline steps). `tests/tree.sh` stays, since `make_references.sh` and `run_stress.sh` still source it.

New in `tests/rhtest`: `tree.py` (`tree_bin`, `tree_src`, `tree_sanitized`, the same logic as `tree.sh`), `compare.py` (the comparison of two `spectrum.out` files with the messages and statuses of `compare_spectra.py`, without numpy; in process instead of one numpy interpreter per comparison), `output.read_spectrum_file` (the layout detection of `compare_spectra.load`), `keywords.has_stokes_input`, in `run.py` `execute_to_log` (program under `/usr/bin/time -v -o time.txt`, output in `log.log`, status as a shell gives it), `peak_rss_mb`, `completed` (0-63) and `log_problem` (the failure text of a log, as the old grep pipeline), `WorkDir(relink=, announce=)`. `rhtest` grows from 552 to 833 lines.

Peak memory is still read from `/usr/bin/time`, not from `wait4`/`ru_maxrss` in Python: a child's `ru_maxrss` starts at the resident size of its parent at the fork (`os.wait4` of `/bin/true` from a Python process reports 11.8 MB; with a 200 MB parent, 217 MB), so the suite's own memory, which grows when it has read spectra, would be a floor under every measurement. The same precondition as before: without `/usr/bin/time` the memory case is skipped with the old warning.

Measured by running the old script (modernize c204d76) and the new one on the same inputs and comparing report and exit status (only the work directory path, the HHMMSS of kept logs and the `2d/mem` megabytes are normalized; the `--help` text differs only in `run_tests.py` for `run_tests.sh` and the missing `# `):
- base build as baseline and candidate, `--exact`, default threads "3 8", the whole suite: 38 passed, identical report, exit 0;
- default tolerance, `--threads "3 8"`, `--only /small`: identical except the I differences of `sph/small` at 3 and 8 threads, which are different in every run of the old script itself (three runs of the old script: 9.4e-13, 2.4e-12, 1.7e-12 at 8 threads: `rhsphere` is not deterministic at more than one thread); `--threads ""`: identical; `--only 1d/ --skip stokes`, an `--only` that matches nothing: identical;
- `--asan` with an AddressSanitizer build (`-DRH_SANITIZE=address`, gcc 13 from a conda env: the system gcc 8.5 has no libasan) with `--threads "2 4" --only small`: 14 passed, 6 ASan checks, same as the old script (again only the `sph` noise);
- upstream baseline (c95bdf6 built with `tests/build_upstream.sh`) against the base build in tolerance mode, `--threads ""`: 11 cases differ from upstream as before, and the report is identical line by line;
- failure paths, report and status identical: a candidate that segfaults (rc=139, log kept), a baseline that segfaults (SKIP), a missing `rhsphere`, a fatal error with TERMINATING_ERROR (rc=70), a sanitizer report, exit status 99, a NaN in the log, only "Segmentation" in the log, `--asan` with a build that is not configured with `-DRH_SANITIZE`, an unknown option, `--baseline` or `--candidate` missing (usage, status 1). `log_problem` was also checked against the bash function on 19 logs (match at the last line, trailing context, 150-character cut, case): identical.
- `ctest`: 44 of 44 with gcc (`-DRH_WARNINGS=ON -DRH_WERROR=ON`) and with icx. `run_tests.py --exact` of the base build (c204d76) against this branch's `-DRH_WARNINGS=ON -DRH_WERROR=ON` build: passed 38, failed 0, skipped 0.

Differences, all in error paths: an option without a value (`--baseline` last on the command line) was an endless loop of the old script (`shift 2` fails and leaves the option; 99 % CPU until killed) and is now an error with status 1; a baseline, candidate or `--asan` directory that does not exist stops with a message and status 1 (before: bash `cd` error, then `missing binary: /rhf1d/rhf1d`, status 1); a `--tol` or `--memtol` that is not a number stops with status 1 (before: handed on to the comparison, not checked here). The old behaviour that a failed comparison keeps the log of the last prepared run directory, not of the compared ones, and that `2d/mem` "tiling failed" keeps the log of the previous case, is kept.

Review follow-up (same branch, later commit). Changes of behaviour compared with the old script:
- `2d/mem` fails, with "no peak memory in .../time.txt", when a peak memory was not measured (`run.peak_rss_mb` returns None); before, a missing measurement counted as 0 MB and the case passed.
- An `OSError` in the work of one case (a directory that cannot be made or removed, a template that cannot be copied, a program that cannot be started, a log that cannot be read) fails that case (`[FAIL] 1d/crd  error: [Errno 13] ...`); the other cases run and the summary and `FAILED:` lines are printed. Checked with a candidate whose `rhf1d/run` is unreadable (all six 1-D cases fail, the 2-D, 3-D and spherical ones are not selected by that run's `--only`).
- A log whose only fatal marker is "Segmentation" now fails the run (`rc=0 Segmentation fault`); the old `log_problem` returned nothing for it and the run passed. A real crash has a nonzero status, so this only matters for a program that prints the word and exits normally.
- `--threads` must be positive integers (status 1 otherwise, also when an unparsable token used to give odd keyword values).
- `keywords.has_stokes_input`: "none" must be a word. `STOKES_INPUT = nonexistent.B` used to count as none (the old grep matched a prefix), so the run's spectrum was read as unpolarized.
- `make_field.py` is taken from the checkout that runs the suite (as before), through `run.make_field`; run directories are made with `run.fresh_dir`; the background-file scan of the program for `mapped_mb` uses `mmap` instead of reading the binary.

`tests/compare_spectra.py` is now a command line over `rhtest.compare` (same options, messages and statuses; 721 invocations on 103 pairs of files give identical stdout, stderr and status before and after, and equal to `rhtest.compare` called directly); its `load()` for `analyze_run.py` returns numpy views of the reader's arrays. The `rhtest.output` readers for pops, spectra and solveray files return `array('d')` in native byte order instead of tuples (the e2e tests that use them pass: 11 of 11).
